# 候选 Modbus 寄存器协议 v1（待 PLC 确认）

本文件描述已实现的软件候选，不证明现有 PLC 工程使用这个协议。最终主从角色、
地址、字序和串口参数必须确认。当前默认服务禁用，不提供可直接用于车辆的配置示例。

## 基础协议

只实现 RTU、03 读保持寄存器；一次读 1..125 个，但有效范围仅是本设备 28 个寄存器。
请求起始地址为 PDU 0 基地址，设备基址来自批准配置，不能直接把 40001 当成线上值。
寄存器内高字节先发；CRC 低字节先发。其他功能码异常 01，地址越界 02，数量/03
请求长度不合法 03；坏 CRC、广播、其他从站地址、响应形式功能码不回复。没有写配置入口。
依据：[应用协议 V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)。

RTU 最长 256 字节，按静默分帧。<=19200 bps 使用 11 位字符时间的 1.5/3.5 倍，
>19200 使用 750/1750 us；支持 8E1、8O1、8N2。不把 UART IDLE 当成 RTU 帧结束。
依据：[串行规范 V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf)，第 12–14 页。
本软件只实现只读用途，不宣称通过该规范全部实现等级/符合性测试。

## 相对偏移

| 偏移 | 内容 | 说明 |
|---:|---|---|
| 0 | 布局版本 | 当前候选为 1 |
| 1 | 快照序号 | 内部发布序号低 16 位，自然回绕，不是有效性标志 |
| 2 | 状态位 | 见下表 |
| 3 | 最新结构合法 SBUS 帧年龄 ms | >65535 饱和；无帧也为 65535，必须结合状态 |
| 4..19 | CH1..CH16 | 原始值、原始顺序；无效时保留历史值，不生成车辆安全值 |
| 20..21 | uint32 有效帧数 | 已发布且未置 frame_lost/failsafe，不累计超时判断次数 |
| 22..23 | uint32 被拒候选数 | 收满 25 字节但 decoder 失败；不是所有噪声/重同步字节数 |
| 24..25 | uint32 本站请求数 | CRC 合法且地址匹配、非响应形式；包含当前请求及异常请求 |
| 26 | 固件版本 | 来自获批配置的 uint16；编码方式需与发布版本记录一致 |
| 27 | 保留 | 0 |

多寄存器计数必须配置 HIGH_WORD_FIRST 或 LOW_WORD_FIRST；UNSET 拒绝启动。
例如 0x12345678：高字在前为 [1234, 5678]，低字在前为 [5678, 1234]。
这不改变每个寄存器内部的高字节先发。两种字序均有测试，最终选择仍待 PLC 确认。
uint32 计数自然回绕；异常应答数、CRC 错误和端口错误仅在诊断结构体，暂不占额外寄存器。

## 状态寄存器（本项目定义，不是 Modbus 标准位）

| bit | 掩码 | 置位含义 |
|---:|---:|---|
| 0 | 0001 | 有帧、传输正常、未报告丢帧/failsafe、已配置且未超时 |
| 1 | 0002 | 最新帧报告 frame_lost |
| 2 | 0004 | 最新帧报告 failsafe |
| 3 | 0008 | 最新帧年龄达到批准阈值 |
| 4 | 0010 | 有历史帧但其发布后出现已知接收故障 |
| 5 | 0020 | 尚无已发布帧 |
| 6 | 0040 | 输入超时阈值不可用 |
| 7 | 0080 | 端口失败或 PLC 活性超时诊断 |
| 8..15 | — | 保留 0 |

bit0 只报告输入数据条件，不是车辆动作许可；bit7 与输入条件独立。PLC 必须同时
检查串口事务成功、状态、序号和年龄，并设置自己的通信/序号停滞超时和控制权互锁。
复制快照之后出现的新故障不能追溯撤回已发字节；应答中的状态描述构造时那份副本。
received_ms 是 SBUS DMA 批次观察时间，年龄不是精确物理端到端延迟测量。

## 合成测试向量

以下只是软件测试地址/数值，不能当成最终 PLC 配置。

- CRC 标准检查字符串 ASCII `123456789` → 数值 4B37，线上 CRC 为 `37 4B`。
- `01 03 00 00 00 0A C5 CD`：地址 1，读 0 基地址 0 起的 10 个寄存器。
- 寄存器值 0x1234 在线上必须为 `12 34`；请求中地址/数量也按高字节先发。
- 故障组合 frame_lost+failsafe+timeout+transport_fault+comm_fault → 状态 009E。
- 无帧+无阈值 → 状态 0060、年龄 FFFF；bit0 必须为 0。

`Tests/test_modbus.c` 逐个验证全部 406 个合法连续读范围、边界地址、字序、CRC
固定向量和独立参考，以及 10000 组变长请求/容量边界。`test_bridge_service.c`
使用合成地址 7、基址 100，检查整段 28 寄存器的 61 字节应答，不代表真实 PLC 通信。
